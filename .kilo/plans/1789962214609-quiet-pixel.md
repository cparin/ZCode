# แผนปรับปรุง SSH Port Forwarding

## เป้าหมาย
เพิ่มความสามารถให้ Desktop ZCode forward port จากเครื่อง remote ผ่าน SSH ได้ใกล้เคียง VS Code Remote-SSH โดยเริ่มจาก local TCP forwarding:

```text
ผู้ใช้เปิด 127.0.0.1:<localPort>
  -> SSH tunnel ของ remote session
  -> <remoteHost>:<remotePort>
```

ขอบเขตระยะแรกเป็น Desktop เท่านั้น, SSH เท่านั้น, bind ที่ `127.0.0.1` เท่านั้น และใช้ SSH connection เดิมของ remote session ไม่สร้าง connection ใหม่ต่อ tunnel

## ขอบเขตและข้อกำหนดผลิตภัณฑ์

- รองรับหลาย forwarded ports ต่อหนึ่ง SSH remote workspace
- รับ `remotePort`, `localPort` แบบระบุเองหรือให้ระบบเลือก local port ที่ว่าง
- มี label/สถานะสำหรับแต่ละ tunnel
- เปิด URL จาก local endpoint ได้เมื่อ protocol เป็น HTTP/HTTPS
- หยุด, retry และลบ tunnel ได้
- ปิด tunnel เมื่อ remote session ถูก dispose, disconnect หรือ reconnect แล้ว session เดิมหมดอายุ
- ไม่ persist tunnel ที่กำลังทำงานใน MVP; persist ได้เฉพาะ future auto-forward configuration
- ปฏิเสธ port ที่ไม่ใช่ TCP, port นอกช่วง 1-65535 และ label ที่ไม่ผ่าน validation
- ไม่ bind `0.0.0.0` และไม่ expose port ออก network โดย default
- Web/mobile remote ไม่รวมใน MVP เพราะ localhost ของ mobile ไม่ใช่ host ที่ถือ SSH connection และต้องใช้ delivery semantics แยกจาก `desktop-continuous`

## Spec ก่อนลงมือเขียนโค้ด

สร้างหรือปรับปรุง spec ในไดเรกทอรีที่เหมาะสมของ repository ก่อน implementation โดยบันทึก:

- behavior, scope และ acceptance cases ด้านบน
- owner ของ state และ lifecycle ของ tunnel
- failure semantics, reconnect/stale-result rules และ security boundary
- migration boundary ว่า MVP ไม่เปลี่ยนพฤติกรรม WSL/Docker และไม่เปิด mobile forwarding
- desktop-only delivery contract

## Ownership และลำดับเหตุการณ์

เจ้าของ mutable state เดียวคือ `PortForwardManager` ที่อยู่ใน Desktop Host และผูกกับ remote session/SSH backend เดิม:

```text
Renderer Ports UI
  -> scoped remote service command
  -> Host PortForwardManager
  -> SSHBackend.forwardOut + local net.Server
  -> state transition
  -> typed port-forward event/result
  -> Renderer projection
```

Lifecycle สำคัญ:

1. UI ส่งคำขอ create พร้อม `remoteSessionId` และ request id
2. Host ตรวจว่า session ยัง online และตรวจ input
3. Manager จอง local port และสร้าง TCP server แบบ loopback
4. เมื่อมี client เชื่อมเข้ามา จึงเปิด SSH `forwardOut` ไป remote host/port และ pipe สองทาง
5. Manager ประกาศ `active` พร้อม local/remote endpoint
6. ทุก operation ตรวจ session generation/identity เพื่อป้องกันผลจาก connection เก่ามาแก้ state ใหม่
7. disconnect/dispose ปิด server และทุก channel แบบ idempotent แล้วประกาศ `closed` หรือ `failed`
8. reconnect ไม่ restore tunnel อัตโนมัติใน MVP และไม่สร้าง tunnel ซ้ำจาก state เก่า

## แผนแก้ไขตามโมดูล

### 1. Shared contract

ปรับ public contract ใน `packages/shared/src/`:

- เพิ่มชนิดข้อมูล port-forward request, record, status และ error ที่มี runtime validation
- เพิ่ม service/channel contract สำหรับ list, create และ dispose tunnel
- เพิ่ม event payload สำหรับ state transition
- ผูกทุก record กับ `remoteSessionId` และ workspace identity ตามกฎ `workspaceIdentity?.trim() || workspacePath`
- แยก transport semantics ของ Desktop ออกจาก Web/mobile อย่างชัดเจน
- เพิ่ม export ผ่าน public entrypoint เท่านั้น

ไฟล์ที่น่าจะเกี่ยวข้อง: `remoteTarget.ts`, `platform.ts`, `channels.ts`, `index.ts` และ contract/service descriptor ของ host ที่มีอยู่จริงหลังตรวจ architecture context

### 2. SSH transport

ปรับ `packages/server/src/remote/ssh-backend.ts` และ public remote entrypoint:

- เพิ่ม primitive สำหรับเปิด direct TCP channel ผ่าน `ssh2` (`forwardOut`)
- ให้ backend ใช้ connection lifecycle เดิมและตรวจ `disposed`/connected ก่อนเปิด channel
- ห่อ channel เป็น typed duplex stream ที่ manager ใช้ได้โดยไม่ expose `ssh2` ไป UI
- จัดการ SSH channel error, remote refusal, backpressure และ half-close
- ไม่ให้ backend เป็นเจ้าของ accepted tunnel list; state list อยู่ที่ Host manager
- เพิ่ม unit tests สำหรับ successful channel, remote refusal, disconnect และ dispose race

### 3. Host/session integration

เพิ่ม manager ในขอบเขต Desktop Host ที่ถือ `HostRemoteConnection`:

- สร้าง `PortForwardManager` ต่อ remote session
- รับคำสั่งจาก scoped service ของ session เดียวกัน
- bind local `net.Server` ที่ `127.0.0.1`
- ใช้ ephemeral port เมื่อ `localPort` ไม่ระบุ
- จำกัดจำนวน tunnelต่อ sessionและจำนวน connection ตาม policy ที่กำหนดใน spec
- close ทุก listener/channel ตอน remote disconnect, session dispose และ Host shutdown
- ส่ง log ระดับ `info/warn/error` ผ่าน logger ที่ repository กำหนด ห้ามเพิ่ม `console.log` ใน UI
- ไม่ให้ main process สร้าง SSH backend หรือเก็บ accepted queue ซ้ำ

ไฟล์ที่น่าจะเกี่ยวข้อง: `packages/desktop/src/host/index.ts`, remote session/attachment registry และ service collection ที่ใช้ scoped remote services

### 4. Renderer state และ UI

เพิ่ม state projection ใน `packages/ui/src/` และ Desktop renderer:

- hook/store อ่าน state จาก remote scoped service ไม่สร้าง authoritative tunnel state ใน Renderer
- UI แสดงรายการ Ports ใน remote workspace
- form เพิ่ม port พร้อม validation และ loading/error state
- row แสดง label, local endpoint, remote endpoint, status และ actions stop/open/retry
- เปิด URL เฉพาะ local endpoint ที่ manager รายงานกลับมา
- รองรับ empty, connecting, active, failed และ closed states
- ใช้ component/design tokens ใน `DESIGN.md`, typography `text-ui-*`, i18n และ light/dark themes
- จำกัด surface ให้ Desktop ก่อน; Web implementation ต้องคืน unsupported อย่าง explicit ไม่แสดง UI ที่ใช้งานไม่ได้

### 5. Persistence และ recovery

MVP:

- ไม่เขียน active tunnel ลง `setting.json` หรือ remote workspace snapshot
- เมื่อ renderer reload ให้ list จาก Host manager แล้วสร้าง projection ใหม่
- เมื่อ Host/SSH session ถูกสร้างใหม่ให้ tunnel เดิมถือว่าปิด
- เพิ่ม persistence เฉพาะเมื่อมี product requirement เรื่อง auto-forward โดยใช้ config แยกจาก runtime state และสร้างใหม่หลัง session online สำเร็จ

## Acceptance และการทดสอบ

### Backend/unit

- เปิด tunnel ไป remote TCP service สำเร็จ
- เลือก ephemeral local port และคืนค่าพอร์ตจริง
- local bind conflict แสดง error โดยไม่ค้าง listener
- remote port ปิด/ปฏิเสธแล้ว tunnel เปลี่ยนเป็น failed และไม่ทำให้ Host crash
- client disconnect ปิด SSH channel เฉพาะ connection นั้น
- SSH disconnect ปิด listener และ channels ทั้งหมด
- dispose ซ้ำได้โดยไม่ throw และไม่ emit duplicate terminal transition
- stale reconnect result ไม่สามารถแก้ tunnel ของ session generation ใหม่

### Desktop integration/E2E

- เชื่อม SSH workspace แล้วสร้าง/list/delete port forward
- เปิด local HTTP server บน remote แล้วเข้าผ่าน local forwarded URL ได้
- ปิด remote session แล้ว local port ไม่ listen ต่อ
- renderer reload แล้วเห็นเฉพาะ tunnel ที่ยังมีอยู่จริง
- local bind ฟังเฉพาะ loopback
- WSL/Docker behavior เดิมไม่เปลี่ยน
- Web/mobile ไม่แสดงความสามารถที่ยังไม่รองรับและไม่ส่งคำสั่งผิด boundary

2. เพิ่ม shared types, runtime schemas และ service contract

4. เพิ่ม Host-owned manager และ lifecycle integration
5. ต่อ scoped service command/event กับ renderer
6. เพิ่ม UI Ports panel และ i18n/design validation
7. เพิ่ม Desktop integration/E2E scenarios และจัดการ failure/reconnect races
8. รัน typecheck, lint, format, architecture check และ package tests

## ความเสี่ยงและการตัดสินใจที่ล็อกไว้

- ต้องไม่ให้ `ssh2` หรือ `node:net` รั่วเข้า UI/shared domain
- ต้องไม่เพิ่ม state owner ที่ main process หรือ Renderer ซ้ำกับ Host
- ต้องไม่ใช้ timeout แทน synchronization ตอน attach/detach หรือ reconnect
- ต้องกำหนด default behavior เมื่อ remote port เป็น HTTP แต่ไม่มี scheme: ใช้ `http://127.0.0.1:<localPort>` เฉพาะ action เปิด URL; tunnel เองยังเป็น TCP
- reverse forwarding, SOCKS, public bind และ mobile forwarding เป็น phase ถัดไป ไม่ควรเพิ่มใน MVP
